OpenAI-compatible · Playwright-driven

An OpenAI-compatible API for Duck.ai — driven by a real browser.

duckai-api opens Duck.ai in a real Chromium session via Playwright, types your prompt into the composer, streams the answer back token by token, and re-exposes it as a standard /v1/chat/completions endpoint. Any OpenAI SDK, Chatbox, Cherry Studio, Open WebUI or Cursor client can talk to it with nothing but a base URL.

🐍 Python 3.11+ ⚡ Streaming SSE 🖥️ Built-in web GUI 🔑 Optional API key 🛡️ Hardened 🐳 Docker ready

Overview

What it is

Duck.ai publishes no public API. This project drives the ordinary web interface in a real browser and repackages the stream as an OpenAI-compatible surface.

🔌

Drop-in compatibility

Speaks the standard /v1/chat/completions and /v1/models contract — streaming and non-streaming.

🎯

Real token streaming

Intercepts Duck.ai's SSE feed and forwards deltas as OpenAI chunks with zero buffering.

🧠

Multiple models

GPT-6 Luna, Claude Haiku 4.5, GPT-5.4 mini, Mistral Small 4, GPT-OSS 120B and Gemma 4 31B — with friendly aliases.

🖥️

Bundled web GUI

A dark ChatGPT-style interface at /, with an optional API-key field and live model picker.

♻️

Memory recycling

The browser page is recycled automatically after N requests or a time interval to keep long runs healthy.

🔒

Hardened by default

Optional API key, constant-time comparison, compliant CORS, generation-scoped stream routing and disconnect handling.

Quick start

Running it locally

Python 3.11 or newer (the bridge uses asyncio.timeout).

  1. Install dependencies

    Create a virtual environment, then install the Python packages and the Chromium build Playwright needs.

    terminal
    # 1. install packages
pip install -r requirements.txt

# 2. download the Chromium binary
playwright install chromium

  2. Start the server

    Defaults to http://localhost:3006. The web GUI is at /, the schema at /docs.

    terminal
    python server.py

  3. Point any OpenAI client at it

    Use http://localhost:3006/v1 as the base URL. If API_KEY is unset, any key value is accepted.

    python
    from openai import OpenAI

client = OpenAI(base_url="http://localhost:3006/v1", api_key="duckai")

stream = client.chat.completions.create(
    model="gpt-6-luna",
    messages=[{"role": "user", "content": "Explain quantum computing in one sentence."}],
    stream=True,
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="", flush=True)

Streaming a completion

curl
curl -N -X POST http://localhost:3006/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $API_KEY" \
  -d '{
    "model": "gpt-6-luna",
    "messages": [{"role": "user", "content": "Hello!"}],
    "stream": true
  }'

Tip: pass "stream": false to receive a single JSON chat.completion object instead of SSE chunks. Model names are validated — an unknown model returns HTTP 400.

Docker

terminal
# build & run with compose
docker compose up --build

# …or plain docker
docker build -t duckai-api .
docker run -p 3006:3006 -e API_KEY="your-secret" duckai-api

The image is based on python:3.11-slim and ships Chromium plus its system libraries, so no host browser is required.

Security

Hardening notes

This project was audited adversarially; the findings below have been addressed in the current revision.

Generation-scoped routing

Every stream frame is tagged with a generation id, so a superseded request can never leak tokens into the next one.

Sanitized rendering

Model output is rendered through DOMPurify after markdown parsing, closing the stored-XSS path in the GUI.

Constant-time auth

API keys are compared with hmac.compare_digest over the Authorization header only.

Bounded lock acquisition

A cancel-safe 30-second lock acquisition prevents a stalled request from blocking the bridge forever.

Disconnect handling

Client disconnects stop the browser generation instead of letting it run on in the background.

Error propagation

Upstream Duck.ai error frames surface as stream errors rather than empty "successful" responses.

Still your responsibility: when API_KEY is unset the API is open, and /health, /docs and the GUI remain unauthenticated. Bind to a trusted network, or set a key and put it behind a reverse proxy.
